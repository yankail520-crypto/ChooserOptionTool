## 1. 概述

数据管道由 GitHub Actions 在每个工作日 UTC 22:00 自动执行一次：

```
原始数据采集            -> 数据质量检查            -> 特征计算               -> 提交到仓库
co_data_pipeline.engine   co_features.iqr_check     co_features.feature_engine   git commit
```

最终产出为日频特征宽表 `feature_daily`，以 JPM 交易日为时间轴，一天一行。

### 2.2 各表字段

各表完整的字段、类型与含义见 **数据开发文档** 第 4 节，这里只列要点。

- **`raw_stock_prices`**：`open` / `high` / `low` / `close` 为前复权价格，`volume` 为按拆股调整后的成交量；`open_raw` / `high_raw` / `low_raw` / `close_raw` / `volume_raw` 为未调整的原始值。
- **`raw_dividends`**：`ex_date`（除息日，主键）、`declaration_date`、`record_date`、`payment_date`、`amount`（每股分红金额，未调整）。
- **`raw_news`**：`date`（发布时间）、`title`、`source`、`url`、`relevance_score`（与 JPM 的相关度）、`sentiment_score`（针对 JPM 的情绪分，由接口 `ticker_sentiment_score` 从 [-1, 1] 映射到 [0, 1]：`(x + 1) / 2`）。
- **`raw_treasury_rates`**：`date`、`rate_1y`（百分比数值，FRED 原始单位）。
- **`raw_vix`**：`date`、`vix`。
- **`raw_option_chain`**：`date`（快照日）、`underlying`、`expiration_date`、`strike`、`option_type`、`bid`、`ask`、`last_price`、`volume`、`open_interest`、`implied_volatility`、`delta`、`gamma`、`theta`、`vega`、`rho`。

## 3. 数据处理

### 3.1 各数据源的清洗

每个数据源通过 `@data_clear` 装饰器绑定专属的清洗函数，`fetch()` 的返回值在返回前自动经过清洗：

| 表名                 | 清洗内容                                                     |
| -------------------- | ------------------------------------------------------------ |
| `raw_stock_prices`   | 日期解析与排序；开高低价按复权因子调整；成交量按拆股调整（见 3.3） |
| `raw_dividends`      | 四个日期字段解析（无法解析时为缺失值），按除息日排序；不做填充 |
| `raw_news`           | 发布时间解析与排序；情绪分从 [-1, 1] 映射到 [0, 1]           |
| `raw_treasury_rates` | 日期解析与排序；`rate_1y` 先前向填充、再后向填充             |
| `raw_vix`            | 日期解析与排序；`vix` 先前向填充、再后向填充                 |
| `raw_option_chain`   | 快照日与到期日解析，数值列类型转换；不做跨记录的填充         |

### 3.2 转为日频与时间对齐

各表经数据对象的 `to_daily()` 转为一天一行、日期列为 `date` 的形式，再以 `raw_stock_prices` 的交易日为时间轴，按 `date` 左连接并入宽表：

- `raw_dividends`：`ex_date` 重命名为 `date`，保留 `amount`，仅除息日有值；
- `raw_news`：按发布日期聚合，`sentiment_score` 为当日各篇情绪分按 `relevance_score` 加权的平均值（当日权重之和为 0 时取简单平均），`news_count` 为当日篇数；
- `raw_treasury_rates`、`raw_vix`：本身为一天一行，原样使用；
- `raw_option_chain`：一天多行，`to_daily()` 按设计抛出 `NotImplementedError`，不进入宽表。

合并时的校验：`date` 列无缺失、无重复（`validate="one_to_one"`），除 `date` 外无同名列，合并前后行数一致，任一不满足即报错。

由于是左连接，其他表中不在股价交易日上的日期（如周末的新闻）不进入宽表；股价交易日上没有对应数据的，相应字段为缺失值。

对齐质量的验证：滚动和差分类特征的有效行数恰好比所依赖列少一个窗口长度（例如 `rate_momentum_20d` 为 2171 行，`rate_1y` 为 2191 行，相差 20），说明合并后的序列中间没有缺失断点。

### 3.3 复权处理

Alpha Vantage 只对收盘价提供复权值（`adjusted close`），开高低价和成交量均为原始成交值。处理方式：

- 开高低价乘以复权因子 `close / close_raw`，与复权收盘价口径一致；
- 成交量乘以该日之后所有拆股系数的乘积（分红不改变股数，只按拆股调整）；拆股系数只在清洗时使用，不保存；
- 原始值以 `_raw` 后缀另行保存。

口径说明：

- Alpha Vantage 的复权方式为**前复权**：以最新价格为基准向过去调整。每当 JPM 发放新的分红，全部历史复权价格都会整体变化，因此股价表采用全量覆盖写入，引用结果时需注明数据版本。
- 与**未调整分红金额**配合计算的指标（如股息率）必须使用 `close_raw`；使用前复权的 `close` 会因早期价格被压低而使股息率系统性偏高。

问题发现过程：数据质量检查在 2000-06-12 发现开高低价的对数收益率约为 −0.41，而复权收盘价在当天无异常。−0.41 接近 ln(2/3)，经核实为大通曼哈顿（JPM 前身）于 2000 年 6 月 12 日生效的 3 拆 2 拆股，说明接口返回的开高低价未经复权。修正后，复权开高低价在该日不再出现跳变。

### 3.4 异常值处理原则

异常值只检测、不删除、不缩尾。金融收益率为厚尾分布，检测出的极端值绝大多数是真实市场事件（见第 4 节），删除会系统性低估波动率，而这些时期恰是后续分析 BSM 失效模式所需要的数据。

后续模型如需对特征缩尾或标准化，相关参数须在时间序列切分后仅用训练集计算，避免前视偏差。

## 4. 数据质量检查

### 4.1 方法

脚本 `co_features/iqr_check.py` 通过 DataCenter 自动遍历所有表和数值列，进行 IQR 异常值检测：

- **变换**：对原始水平值直接做 IQR 会把有趋势的序列整段标记，因此按规则自动选择：
  - 始终为正且不贴近 0（价格、VIX、成交量）→ 对数收益率
  - 存在 0/负值或贴近 0（利率）→ 差分
  - 特征表中的派生特征 → 水平值
  - 样本过少、离散或稀疏的列 → 跳过
  - 自动判断不适用的列在 `OVERRIDES` 中手动指定（如 `sentiment_score` 检测水平值）
- **阈值**：k = 3，以适应厚尾分布
- **窗口**：按日历时间滚动 365 天；稀疏表（日期间隔中位数超过 5 天）使用全样本
- **去重**：特征表中从原始表透传的列、`daily_return` 以及未复权的 `_raw` 列不重复检查
- 检测结果只写日志和报告，不修改数据；GitHub Actions 中报告作为构件上传，保留 30 天

### 4.2 结果

## 5. 特征工程

### 5.1 特征计算框架

特征以类的形式定义在 `co_features/features/` 目录下，由 FeatureEngine 自动发现和执行：

- 特征之间的依赖用类继承表达：B 依赖 A 的结果，则 B 继承 A，并在 `compute()` 中先调用 `super().compute(df)`；
- 引擎只实例化继承链末端的"叶子"类，祖先类的计算通过继承链自动完成；
- 所有特征只使用当日及之前的数据（`shift` / `diff` / `rolling` / 前向填充），不增删行。

详细机制见 **数据开发文档** 第 1.3 节。

### 5.2 派生特征

| 特征                      | 计算方式                                      | 窗口  | 依赖                  | 含义                                                 |
| ------------------------- | --------------------------------------------- | ----- | --------------------- | ---------------------------------------------------- |
| `daily_return`            | ln(close_t / close_{t−1})                     | 1 行  | `close`               | 日对数收益率                                         |
| `rolling_vol_20d`         | std(daily_return) × sqrt(252)                 | 20 行 | `daily_return`        | 年化历史波动率                                       |
| `vix_jpm_correlation_20d` | corr(daily_return, VIX 日变化率 `pct_change`) | 20 行 | `daily_return`、`vix` | JPM 收益与市场波动预期变化的联动程度                 |
| `rate_momentum_20d`       | rate_1y_t − rate_1y_{t−20}                    | 20 行 | `rate_1y`             | 利率变化量（百分点）                                 |
| `dividend_growth`         | `amount` 前向填充后逐行 `pct_change`          | —     | `amount`              | 分红变化当天为环比增长率，其余日期为 0               |
| `dividend_yield`          | `amount` 前向填充 × 4 / `close_raw`           | —     | `amount`、`close_raw` | 股息率 q：最近一次已除息分红的年化值除以未调整收盘价 |

相关性使用收益率与变化率而非价格水平计算，因为价格水平通常非平稳，直接计算相关系数容易得到虚假的高相关。

`dividend_yield` 的口径选择：分子用"最近一次分红 × 4"，使股息率在分红调整后立即反映新水平；分母用 `close_raw`，与未调整的分红金额口径一致。

### 5.3 并入宽表的原始字段

以下字段来自 raw 层，直接作为模型输入使用：

| 字段              | 来源                 | 含义                                   |
| ----------------- | -------------------- | -------------------------------------- |
| `sentiment_score` | `raw_news`           | 当日 JPM 新闻情绪分（相关度加权，0–1） |
| `news_count`      | `raw_news`           | 当日 JPM 新闻篇数                      |
| `vix`             | `raw_vix`            | 市场整体波动预期                       |
| `rate_1y`         | `raw_treasury_rates` | 1 年期无风险利率                       |
| `amount`          | `raw_dividends`      | 除息日的每股分红金额                   |
| 行情字段          | `raw_stock_prices`   | 复权与未复权的开高低收、成交量         |

项目文档要求的特征均已覆盖：传统特征（滚动波动率、日收益率、分红增长率）与进阶特征（VIX-JPM 相关性、利率动量、情绪分），合计超过 10 个。

某次运行时 `feature_daily` 中各字段的有效行数：行情字段 6763；`daily_return` 6762；`rolling_vol_20d` 6743；`dividend_growth` 6718；`rate_1y` 2191；`vix` 2192；`rate_momentum_20d` 2171；`vix_jpm_correlation_20d` 2172；`sentiment_score`、`news_count` 1798；`amount` 108。分红原始表 113 行，并入宽表后为 108 行，差额为不在股价交易日上的除息日记录。

### 5.4 股息率的外部核对

以 2026-09-22 为例：

| 口径                                   | 年化分红        | 前收盘价 | 股息率 |
| -------------------------------------- | --------------- | -------- | ------ |
| `dividend_yield`                       | 1.50 × 4 = 6.00 | 340.00   | 1.76%  |
| Yahoo Finance Forward Dividend & Yield | 1.65 × 4 = 6.60 | 340.00   | 1.94%  |

两者均可用 Yahoo Finance 的前收盘价 340.00 精确复现。差异来自 JPM 于 2026-09-15 宣布、2026-10-06 除息的分红上调（1.50 → 1.65）：本项目以除息日作为新分红金额的生效时点，Yahoo 以宣布后的最新分红计算。

股息率时序图（`co_test/ts_dividend_yield.py`）显示，2012 年以后的股息率大致在 2%–4% 之间，2020 年 3 月升至约 4.5%，近期约 1.8%；2009 年分红削减、2020 年 3 月股价下跌等变化均与历史吻合。

## 6. 自动化

GitHub Actions 工作流（`.github/workflows/daily_update.yml`）的步骤：

1. `python -m co_data_pipeline.engine`：按 `configs/enabled_sources.json` 采集原始数据，各数据源按自身策略写入（股价全量覆盖，其余增量追加）；
2. `python -m co_features.iqr_check`：数据质量检查，报告作为构件上传；
3. `python -m co_features.feature_engine`：计算特征宽表；
4. 数据有变化时自动提交到仓库。

由于前复权的历史价格会随新分红变化，每次提交即为一个数据快照。引用任何实证结果时，应同时注明对应的提交哈希。
